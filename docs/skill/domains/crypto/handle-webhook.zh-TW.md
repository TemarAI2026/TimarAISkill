# 處理 webhook

## 先確認什麼

在實作 webhook 接收端之前，先確認你手上的公開整合合約是否已明確以下內容：

- webhook 的實際發送方與觸發場景
- 請求標頭、簽名或驗簽規則
- 事件負載結構與狀態欄位
- 重試策略、逾時要求與成功回應約定

如果這些內容沒有在目前公開文件中明確說明，不要自行補完或假設，請先回到最新公開文件與你的對接約定重新確認。

## 接收端建議

讓實作保持保守、可稽核、可重放：

- 記錄請求 ID；如果上游沒有提供明確請求 ID，記錄你自己的接收追蹤 ID，並把它與原始請求綁定
- 保留原始請求本文與重要請求標頭，方便排查與對帳
- 以事件唯一鍵或訂單號加狀態變化設計冪等處理，避免重複通知造成重複入帳或重複出款確認
- 只有在你自己的整合合約明確允許時，才把 webhook 視為訂單最終狀態來源
- 對收到的訂單號、金額、幣種、網路等資訊，先回查你自己的訂單紀錄再更新業務狀態
- 在正式實作前，再次檢查目前公開的狀態文件、回應慣例與錯誤處理文件

## 常見錯誤

- 在沒有明確公開規則的情況下，自行假設 webhook 欄位或簽名演算法
- 不記錄請求 ID 或原始請求本文，導致無法排查重試與重複通知
- 沒有冪等設計，重複通知時重複更新訂單
- 收到通知後直接改狀態，而不與本地訂單和目前整合合約進行比對
