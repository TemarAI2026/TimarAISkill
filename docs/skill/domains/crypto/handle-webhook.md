# 处理 webhook

## 先确认什么

在实现 webhook 接收端之前，先确认你手上的公开集成合同是否已经明确以下内容：

- webhook 的实际发送方和触发场景
- 请求头、签名或验签规则
- 事件负载结构与状态字段
- 重试策略、超时要求和成功响应约定

如果这些内容没有在当前公开文档里明确说明，不要自行补全或假设，先回到最新公开文档和你的对接约定核对。

## 接收端建议

保持实现保守、可审计、可重放：

- 记录请求 ID；如果上游未提供明确请求 ID，记录你自己的接收追踪 ID，并把它与原始请求绑定
- 保留原始请求体和关键请求头，方便排查与对账
- 以事件唯一键或订单号加状态变化设计幂等处理，避免重复通知造成重复入账或重复出款确认
- 只有在你自己的集成合同明确允许时，才把 webhook 作为订单最终状态来源
- 对收到的订单号、金额、币种、网络等信息，回查你自己的订单记录再做业务更新
- 在正式实现前，重新检查当前公开的状态文档、响应约定和错误处理文档

## 常见错误

- 在没有明确公开规则的情况下，自行假设 webhook 字段或签名算法
- 不记录请求 ID 或原始请求体，导致无法排查重试和重复通知
- 没有幂等设计，重复通知时重复更新订单
- 收到通知后直接改状态，而不与本地订单和当前集成合同进行比对
